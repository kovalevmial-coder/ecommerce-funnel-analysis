## Итоговый вердикт (согласован: README = ноутбук 05 = отчёт)

- **Узкое место — view→cart**: потеряно 3 492 271 сессий (81.6 % просмотров) против
  859 491 на cart→purchase; end-to-end 2.7 %.
- **Худший decision-relevant ярус — premium** (view→cart 5.82 % vs budget 23.63 % /
  mid 15.85 %): подтверждено pre-registered тестами (3 YES-пары: budget-mid, budget-premium,
  mid-premium). Luxury — 0.94 % сессий, ниже 1 %-бара объёма: реально, но не actionable.
- **B и C — статистически реальны, практически нет**: rel uplift 4.9 % / 7.3 % < 10 %-бара.
- **Рекомендация**: pre-registered A/B на discovery премиум-товаров (фильтры/PDP), P₀ 5.82 %,
  MDE +10 % rel, n=26 608/группу, ~3 недели — выполнимо.
- **Ограничения**: ярусы — прокси атрибутов товара, не юзеров; причинность не заявлена;
  budget-mid чувствителен к определению яруса (находка nb06); A/B — предложение, не прогон.

## Почему это стоит называть готовым (честная рефлексия)

- Числа в README пере-выведены из `src/`, а не переписаны из ноутбукова вручную —
  каждый пункт трассируется до артефакта; тест 80/80 зелёный; ноутбуки `errors=none`;
  один коммит = одно логическое изменение (44 коммита).
- «Verdict-flip» не скрывался: budget-mid при квартильных границах меняет вердикт —
  это зафиксировано как чувствительность определения, а не спрятано.
- Границы интерпретации написаны в README, а не в мелкий шрифт: автооценка «премиум-
  покупатели» заменена на «сессии с премиум-товарами».

## Как переиспользовать для другого датасета

1. **Данные**: замени CSV → `scripts/etl_events.py` (события) + `scripts/etl_pipeline.py`
   (сессии: последовательности, has_view/cart/purchase, сегменты; фиксированный `random_state`).
2. **Расчёт**: `src/` остаётся как есть — тесты (`tests/`, 80, сверка со statsmodels/scipy)
   гарантируют корректность формул; ярусы и пороги — параметры (не хардкод).
3. **Вывод**: тот же конвейер pre-registration → ноутбуки 02–06 → README; правило
   практической значимости (CI ≠ 0, |rel| ≥ 10 %, объём ≥ 1 %) — переиспользуемый рецепт
   против «p < 0.05 значит внедрять».
4. **Прочее**: новая рынка → проверить единицу анализа, потери, отсутствие NaN-логики и
   единиц валют ДО тестов (правило «данные прежде всего»).

## Подводные камни этого этапа и проекта в целом

1. **README, полный «красивых» цифр без трассировки** — главный риск финального слоя:
   каждый number обязан иметь источник (здесь — source-of-truth из `src`, сверка regex).
2. **Согласованность вердиктов между артефактами** — расхождение README/ноутбук/отчёт
   ловится только сквозной сверкой формулировок; блока «вердикт-переменные» nb05 —
   де-факто канон.
3. **Bijection картинок** — README не должен ссылаться на несуществующий `assets/*.png`;
   проверено автоматом (9/9 в обеих README).
4. **Порядок коммитов как доказательство шлюза** — pre-registration обязан стоять раньше
   confirming-ноутбуков в `git log`; проверяется, а не декларируется.
5. **Не переусердствовать с дизайном README** — баннер берём из существующего исполнительного
   графика (funnel), не плодим новые.
