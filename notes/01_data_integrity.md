> — целостность данных, EDA и распределение цен, строго описательные.
> Проект: воронка конверсии интернет-магазина косметики,
> датасет E-commerce Events History (Kaggle, mkechinov), 2019-10 — 2020-02.

## Цель этапа

Сделать «проверку током» перед любыми выводами (золотой стандарт №1 из AGENTS.md):

1. **Интеграти-отчёт** — базовые числа: события, пользователи, сессии, пропуски, аномалии.
2. **Сессионные диагностики** — «грязные» пути воронки: покупка без корзины, корзина без просмотра.
3. **Распределение цен** — чисто «фичевое» (feature) представление, которое послужит для фиксации
   ценовых ярусов в pre-registration — **без** какого-либо взгляда на исходы по ярусам.

Ноутбук намеренно **не делает ни одного утверждения о значимости** — это описательный этап.

## Зачем это важно

**Почему единица анализа (unit of analysis) решается раньше процентов?** Воронка и все тесты
считаются на уровне сессии, а не строки. Если сессия определена мимо (голый `user_session`),
272 переиспользованных у разных пользователей ID склеят чужие пути: 272 из 4 535 941 ≈ 0,006 %
сессий загрязнены, но это не значит, что про них можно забыть — просто масштаб
задокументирован. Строка ≠ сессия: на 20,69 млн строк событий приходится лишь 4,54 млн сессий
и 1,64 млн пользователей; считать на строках значило бы учредить «анализ повторений», где
p-value утверждал бы что-то ни про каких пользователей.

**Почему честно фиксируем аномалии, а не «чистим» молча?** Точные дубликаты строк (1,1 млн,
5,4 %), 131 строка с отрицательной ценой (минимум −79,37), одна покупка по цене 0 — природа
этих строк реальна (возвраты, коррекции), решение о них принимается явно, а не невидимым
дропом. Пропуски `brand` 42,3 % и `category_code` 98,3 % (считаны и с `""`, и с NULL) закрывают
продуктовую сегментацию — это не «мы не захотели», а «в данных физически нет».

**Почему диагностики «покупка без корзины» обязательны?** 18,85 % покупок случаются без
события cart в той же сессии; 20,02 % картов не имеют view. Это реальное поведение (прямые
покупки, корзина из другой сессии), а не шум. Оно ломает интуицию «шаг за шагом» и диктует
конструкцию воронки: только индикаторы достижения шагов (has_view/has_cart/has_purchase),
никаких фильтров «дошёл по шагам подряд».

## Ключевые термины

- **Единица анализа (unit of analysis)** — объект метрики; здесь сессия (пара
  «сессия + пользователь» при интеграти, сам `user_session` в сессионных таблицах).
- **Интеграти-отчёт (integrity report)** — 15 ключей-метрик из `src.eda.integrity_report`:
  объём, единицы, пропуски, типы, диапазоны, аномалии.
- **Reached-step indicator (индикатор достижения шага)** — бинарный флаг «в сессии было ≥1
  события шага», а не правило о порядке шагов.
- **Описательный vs подтверждающий (descriptive vs confirmatory)** — ноутбук 01 показывает
  «что видно»; значимость утверждает только этап 06 на зарегистрированных гипотезах.

## Что сделано

### Интеграти-числа (ground truth, сверены с этапом 01)

| Показатель | Значение |
|---|---|
| Событий (строк) / пользователей / сессий | 20 692 840 / 1 639 358 / 4 535 941 |
| Пропуск `brand` | 42,3 % |
| Пропуск `category_code` | 98,3 % |
| Точно дублирующиеся строки | 1 109 098 (5,4 %) |
| Диапазон цен | −79,37 … ≈327,78 |
| Покупок по цене 0 | 1 |
| Строк без `user_session` | 4 598 |
| ID сессий, присвоенных разным пользователям | 272 |

> **Порядок пропусков исправлен относительно плана.** План-обобщение «98,3 % / 42,3 %»
> стояли в обратном порядке; живой `integrity_report` + сырой parquet дают `brand` = 42,3 %,
> `category_code` = 98,3 %. Ground truth — за кодом, не за планом (AGENTS §7).

### Сессионные диагностики

- **Покупка без корзины (purchase-no-cart)**: 29 328 сессий = 18,85 % от 155 617 покупок.
- **Корзина без просмотра (cart-no-view)**: 197 350 сессий = 20,02 % от 985 780 корзин.

Разница integratic-подсчёта (29 333 / 197 374) и сессионного (29 328 / 197 350) — 272
переиспользованных ID сессий, учтённых парой `(user_session, user_id)` в отчёте;
задокументирована прямо в ноутбуке.

### Распределение цен — только фичи

Гистограмма + децили (персентили) медианной цены сессии, сохранены в
`assets/integrity_price_distribution.png`. Раздел явно оговорён: это **строительный
материал для ярусов**, исходы по ярусам здесь не смотрят. Фиксация ярусов —
в `reports/pre_registration.md` (этап 05, Task 3).

### Почему это строго описательный ноутбук

Ни в одной ячейке нет `p-value`, z-статистики или доверительного «значимо/незначимо».
Любой подобный тезис сейчас был бы **подгонкой под найденный результат** (p-hacking):
пороги и гипотезы зарегистрированы ПОСЛЕ этого ноутбука, т.е. до просмотра исходов
сегментов. Маркер-ячейка «nothing here is a significance claim» — не формальность,
а контракт этого этапа.

## Выводы

- Данные жизнеспособны: объём большой, воронка получит узкие CI — вопрос будет
  не «различимо ли», а «стоит ли действовать» (практическая значимость, этап 05).
- Воронка «грязная» по своей природе: ~19 % покупок без корзины и ~20 % корзин без
  просмотра вынуждают строить воронку на индикаторах достижения, а не на порядке.
- Продуктовая сегментация невозможна: `category_code` пуст на 98,3 %, `brand` — на 42,3 %.
- Существенных «дыр» в объёме ценовых сегментов нет — распределение позволяет зафиксировать
  четыре яруса для подтверждающего этапа.

## Подводные камни (pitfalls)

1. **Строка ≠ сессия ≠ пользователь.** Считать на строках — значит «анализировать повторения»,
   а не людей; всегда спускайся до единицы анализа явно.
2. **Пропуск = NULL **и** `""`.** Считая только NULL, `category_code` недооценишь (реальность —
   98,3 %).
3. **Порядок шагов не выполняется.** purchase без cart и cart без view — поведение, а не
   ошибка; фильтр «по шагам подряд» был бы враньём.
4. **Распределение цен — фича, не реклама.** Смотреть на децили и тут же «вывод о тирах» —
   это уже анализ результатов до pre-registration.
5. **Числа из памяти — не источник правды.** Каждая цифра порождается кодом заново; живой
   подсчёт сильнее планового ожидания.
