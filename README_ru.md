## Введение

Проект анализирует воронку покупки **(просмотр → корзина → покупка)** интернет-магазина косметики за пять полных месяцев (октябрь 2019 — февраль 2020) на публичном датасете Kaggle *E-commerce Events History in Cosmetics Shop* от mkechinov.

Работа отвечает на один бизнес-вопрос: **где воронка теряет больше всего клиентов, и сосредоточена ли потеря в сегменте, на который мы можем повлиять?**

В отличие от типичной папки разведочных ноутбуков, проект предрегистрирован: семейства гипотез, уровень значимости, поправка на множественные сравнения и правило практического решения были зафиксированы в `reports/pre_registration.md` *до* запуска конфирматорного анализа. Конфирматорные сравнения в ноутбуке 04 в точности следуют этому документу; ноутбук 06 проверяет вердикт на устойчивость к разумным переформулировкам и честно сообщает, что меняется.

Главное в одной строке: воронка теряет большую часть объёма на шаге **просмотр → корзина**, потеря сосредоточена в **премиальном** ценовом сегменте, а рекомендованное действие — это рассчитанный по объёму A/B-тест на обнаружение премиальных товаров.

## Технологический стек

- **Python 3.12** — среда исполнения, подтверждена тестовым набором.
- **polars** — загрузка данных, инженерия признаков сессий, агрегация воронки и все сегментные расчёты. Polars выбран по двум причинам: ленивая/потоковая обработка (`LazyFrame`) держит набор 2.3 ГБ CSV вне памяти и никогда не материализует его целиком, а Arrow-native колоночный движок делает session/reached-step джойны достаточно быстрыми для локальной итерации.
- **numpy / scipy** — z-тесты, критерий хи-квадрат, доверительные интервалы (Wilson, Wald).
- **statsmodels** — нормальная аппроксимация для расчёта размера выборки и мощности, BH-FDR поправка на множественность (используется только для *перекрёстной проверки* самописных функций в `src/inference`).
- **matplotlib** — каждый зафиксированный график в `assets/`, построенный из `src/plots.py`.
- **jupyter (nbclient / nbformat)** — ноутбуки *генерируются программно* сборщиками `notebooks/build_*.py` через общий раннер `scripts/build_notebook.py`, поэтому каждый вывод `.ipynb` воспроизводим и имеет `errors=none`.
- **pytest** — по одному тесту на модуль расчётов, включая сверку с `statsmodels`/`scipy`.
- **uv** — управление зависимостями, рекомендуемый инструмент окружения.

## Данные

**Источник:** [E-commerce Events History in Cosmetics Shop](https://www.kaggle.com/datasets/mkechinov/ecommerce-events-history-in-cosmetics-shop) (Kaggle, mkechinov). Пять полных месяцев сырых поведенческих событий (view, cart, purchase, remove_from_cart) интернет-магазина косметики.

| Величина | Значение |
|---|---|
| Событий | 20,692,840 |
| Пользователей | 1,639,358 |
| Сессий (уникальных `user_session`) | 4,535,941 |
| Окно наблюдения | 2019-10 … 2020-02 (5 полных месяцев, без пилотного месяца) |

Единица анализа — **сессия** — одна строка на `user_session`, а не строка события и не пользователь. Это зафиксировано в предрегистрации и задокументировано в `src/funnel.py`.

У датасета есть особенности, которые этап целостности задокументировал, а анализ учел:

| Особенность | Результат проверки |
|---|---|
| `brand` пропущен | 42.3% строк |
| `category_code` пропущен | 98.3% строк (пустая строка считается пропуском) |
| Точные дубликаты строк | 1,109,098 полностью дублированных строк |
| Диапазон `price` | -79.37..327.78 EUR; 0.50% строк с ценой 0 — включая **1 покупку** по цене 0 |
| Нет колонок device / channel / geo | сегментацию пришлось переориентировать на *атрибуты товара* (ценовые сегменты) |
| Переиспользование session-id | 272 сессии переиспользованы разными пользователями |
| Деталь сессий | 4,598 строк с пустым `user_session` исключаются (строка не может принадлежать сессии) |

Поскольку `brand` и `category_code` в основном отсутствуют, а контекста устройства пользователя нет, конфирматорный дизайн сравнивает **ценовые сегменты** (атрибут товара, вычисляемый по сессии), а не демографические сегменты или сегменты по привлечению.

## Методология

### Определение воронки (индикаторы достигнутых шагов)

Каждая сессия получает булевы индикаторы шагов: `has_view`, `has_cart`, `has_purchase` (≥1 событие этого типа). Шаги независимы — сессия, купившая без события корзины, попадает только в `has_purchase`, а jump-диагностика ниже точно оценивает такие переходы.

Три показателя, сравниваемые в проекте:

| Показатель | Определение |
|---|---|
| просмотр→корзина | P(cart \| view) — сессии с корзиной среди сессий с просмотром |
| корзина→покупка | P(purchase \| cart) — сессии с покупкой среди сессий с корзиной |
| просмотр→покупка | P(purchase \| view) — сессии с покупкой среди сессий с просмотром |

Точечные оценки приводятся с точными **95% доверительными интервалами Wilson** (граница, учитывающая гипергеометрическую природу, `src/funnel`/`src/inference`).

### Ценовые сегменты (объясняющая переменная)

Зафиксированные бизнес-диапазоны, закрепленные до анализа «сегмент × исход» (предрегистрация §2):

| Сегмент | Диапазон (EUR) | Сессий |
|---|---|---|
| budget (эконом) | `< 5` (включая 0 и отрицательные цены) | 2,148,161 |
| mid (средний) | `[5, 30)` | 1,942,774 |
| premium (премиум) | `[30, 150)` | 402,568 |
| luxury (люкс) | `≥ 150` | 42,438 |
| **Итого** | | **4,535,941** |

Во всех четырёх диапазонах ≥ 500 сессий, поэтому предрегистрированное правило объединения не срабатывает (проверено 2026-09-22).

### Конфирматорные семейства

- **Семейство A** — ценовой сегмент × просмотр→корзина: один критерий хи-квадрат 4×2 плюс шесть парных z-тестов для долей, на сессиях с просмотром.
- **Семейство B** — тип визита × корзина→покупка: новые против возвращающихся сессий, один двухвыборочный z-тест на сессиях с корзиной.
- **Семейство C** — будний/выходной день × корзина→покупка: один двухвыборочный z-тест на сессиях с корзиной.

### Правило принятия решения (предрегистрировано, зафиксировано до любых выводов)

$$\text{decision-relevant} \iff \big(0 \notin \text{95%CI}(p_i - p_j)\big) \;\land\; \Big(\big|\tfrac{p_i - p_j}{p_{\min}}\big| \ge 0.10\Big) \;\land\; \big(\text{affected sessions} \ge 0.01 \cdot 4{,}535{,}941\big).$$

Конкретно: различие **практически значимо только если выполнены все три условия**:

1. 95% ДИ разности не содержит 0 (направление статистически установлено), **и**
2. |относительный прирост| ≥ 10% от нижнего (базового) показателя, **и**
3. затронутый объём ≥ 1% всех сессий (≥ 45,360 из 4,535,941).

Множественность: α = 0.05 двусторонний для каждого теста; шесть парных тестов семейства A образуют одно семейство → **поправка Бонферрони по семейству** α* = 0.05/6 ≈ 0.0083. BH-FDR приводится только как проверка чувствительности (никогда не задаёт правило отбраковки). Если ожидаемое число в ячейке `n·p < 5` (или `expected_min < 5` для хи-квадрат) — для этого сравнения **тест не проводится**, ставится флаг `sparse=True`, результат приводится описательно.

**Следствие по замыслу:** люкс (42,438 сессий = 0.94% всех сессий) может быть статистически подтверждён в сравнении, но никогда не может быть практически значимым — он ниже гейта «1% объёма». Это осознанное следствие предрегистрированного правила, а не артефакт данных.

### Соотношение размера выборки и мощности

Используется для оценки *возможностей* конфирматорных тестов и для расчёта A/B-предложения (предрегистрация §7 — контекст возможностей, никогда не подстройка зафиксированного правила):

$$n = \left[\frac{z_{1-\alpha/2}\,\sqrt{2\bar{p}(1-\bar{p})} \;+\; z_{\text{power}}\,\sqrt{p_0(1-p_0) + p_1(1-p_1)}}{\text{mde}}\right]^2$$

## Результаты

### Основная воронка (ноутбук 02, CI Wilson)

| Показатель | Точечная оценка | Дроби | 95% ДИ |
|---|---|---|---|
| просмотр→корзина | 0.184182 | 788,430/4,280,701 | [0.183816, 0.184550] |
| корзина→покупка | 0.128111 | 126,289/985,780 | [0.127452, 0.128772] |
| просмотр→покупка | 0.027195 | 116,412/4,280,701 | [0.027041, 0.027349] |

Те же ставки, нарисованные так, как воронку читает бизнес, — как сужающиеся ступени объёма (абсолютные сессии, дошедшие до каждого конвертирующего шага), а не как столбчатая диаграмма:

![Funnel stages](assets/funnel_stages.png)

Ширина трапеций пропорциональна абсолютному числу сессий; чтение «сверху вниз» — это height-чтение столбчатой диаграммы выше (`funnel_chart.png`, баннер), тогда как этот график несёт volume-shape-чтение — где воронка физически сужается, — которое мотивирует рамку абсолютных потерь ноутбука 05.

Jump-диагностика воронки (ноутбук 02): **29,328** сессий с покупкой без корзины (18.85% из 155,617 сессий с покупкой), **197,350** сессий с корзиной без просмотра (20.02% из 985,780 сессий с корзиной), **3,431,995** сессий с просмотром без корзины.

Обе категории «прыжков» — аномалии, которые стоит объяснить, а не отбросить. Данные не позволяют выбрать между причинами — это **гипотезы, а не выводы**, и анализ относится к ним именно так:

- **Продолжение в другой сессии.** Идентификаторы сессий произвольны; пользователь может посмотреть товар в одной сессии, а купить позже из новой сессии (сохранённая корзина, покупка по ссылке из письма или со страницы товара) — тогда сессия покупки корректно не содержит событий корзины/просмотра. Юзер-уровневая воронка nb06 отчасти и есть этот эффект.
- **Прямые ссылки / внешний вход.** Уведомления, письма, реклама или прямые ссылки на сохранённый товар могут провести заказ через сессию без предшествующих событий корзины/просмотра.
- **Покупка в один клик / ускоренный размен.** Способ чекаута, пропускающий событие корзины в рамках сессии, тоже выглядел бы как «покупка без корзины».
- **Особенности сбора данных.** В датасете известны артефакты загрузки (1,109,098 дубликатов строк, 272 переиспользованных идентификатора сессии); пробел трекинга, молча теряющий события просмотра/корзины, раздул бы счётчики «прыжков» так же.

Практический вывод: условные ставки воронки выше — **не** буквальный путь одного пользователя; они агрегируют сессии, а «прыжки» ограничены и измерены (≤20% знаменателя), а не молча проигнорированы.

### Где теряется объём (ноутбук 05)

![Диагностика узкого места](assets/bottleneck_diagnostic.png)

Доминирующая абсолютная потеря — на шаге **просмотр → корзина**: теряется **3,492,271** сессия (в 4.06 раза больше, чем 859,491 потерянных на корзина→покупка). Потеря сосредоточена в **премиальном** сегменте — худшем практически значимом сегменте на узком месте (ниже).

### Семейство A — ценовой сегмент × просмотр→корзина (ноутбук 04, предрегистрировано)

Общий хи-квадрат: χ² = 91674.404, df = 3, p ≈ 0, expected_min = 7699.6 → тест валиден. Порядок показателей просмотр→корзина: **budget 23.6303% > mid 15.8503% > premium 5.8162% > luxury 4.2795%**.

## Бизнес-эффект

**Исполнительный вердикт.** За задокументированное пятимесячное окно воронка теряет большинство клиентов на шаге **просмотр→корзина**: 3,492,271 из 4,280,701 сессий с просмотром (81.6% просмотров так и не доходят до корзины) против 859,491 потерянных на корзина→покупка, и лишь 2.7% всех просмотров заканчиваются покупкой — объём теряется до корзины. Потеря сосредоточена в **премиальном** ценовом сегменте: его показатель просмотр→корзина равен 5.82% против 23.63% у эконом-сегмента и 15.85% у среднего — разрыв, который предрегистрированные тесты в ноутбуке 04 подтвердили как практически значимый (люкс ниже — 4.28%, но при 0.94% сессий он попадает под предрегистрированный гейт «1% объёма», поэтому он реален, но не является целью для действия). Семейство B (новые против возвращающихся) и семейство C (будни против выходных) статистически значимы (p < 10⁻¹⁶), но практически несущественны — их относительный прирост (4.87% и 7.32%) остаётся ниже практического барьера 10%, поэтому работа с ними сдвинула бы воронку меньше, чем обычная недельная волатильность метрики магазина.

**Рекомендуемое действие:** провести предрегистрированный A/B-тест, улучшающий **обнаружение премиальных товаров** (фильтры каталога / содержимое страницы товара, PDP), с целевым приростом +10% относительного к показателю просмотр→корзина в премиум-сегменте.

![Кривая конверсии по цене](assets/price_conversion_curve.png)

Разведочная кривая «конверсия по цене» (ноутбук 03) — описательный контекст того же механизма: именно у премиальных сессий конверсия обрушивается — кривая мотивирует гипотезу A/B, но сама по себе её не подтверждает.

### Расчёт A/B-теста (предложение, из ноутбука 05)

| Параметр | Значение |
|---|---|
| Гипотеза | H1 — эксперимент по обнаружению/странице товара в премиуме (только премиальные страницы) |
| Единица / рандомизация | сессия, 50/50, отбор = сессии с просмотром премиальных товаров |
| Метрика | просмотр→корзина среди премиальных сессий с просмотром |
| p₀ (контроль) | 5.8162% (наблюдаемый показатель просмотр→корзина в премиуме) |
| MDE | +10% относительного (= 0.58 п.п. абсолютных) |
| α (двусторонний) / мощность | 0.05 / 0.80 |
| **Требуемый объём на группу** | **26,608** |
| Доступно сессий просмотра премиума | 397,736 за окно → ≈ 18,317/неделю |
| Ожидаемая длительность | **≈ 3 недели** (n = 27,475 на руку на плановом запуске, мощность ≈ 0.812) |
| Гейт вердикта | двусторонний z при α = 0.05; запускать, если ДИ не содержит 0 **и** относительный прирост ≥ 10% **и** затронутый объём ≥ 45,360 |

Дизайн **выполним** на наблюдаемом трафике премиума и честно помечен: **это предложение.** Тест не был проведён; он выходит за рамки этого проекта (ноутбук 05, §4).

## Ограничения

Прочитайте перед тем, как действовать по вердикту:

- **Ценовые сегменты — это прокси атрибутов товара, а не характеристик пользователя.** «Премиальная» сессия — та, что просматривала товары с премиальной ценой; это ничего не говорит о типе покупателя. Утверждений о «премиальных клиентах» нет.
- **Заявление о причинности отсутствует.** Сегмент не рандомизирован — каждое сравнение выше это ассоциация на наблюдаемых сессиях. Причинность устанавливается только предполагаемым (не проведённым) A/B-тестом.
- **Контраст budget–mid чувствителен к определению границ сегментов** (проверка устойчивости, ноутбук 06): при другом проведении границы между budget и mid конкретный вердикт ДА меняется на НЕТ. Пары budget–premium и mid–premium устойчивы к переопределению; рекомендация опирается только на устойчивые пары.
- **Семейства B и C реальны, но не пригодны для действий.** Статистически установлены при p < 10⁻¹⁶, практически ниже барьера 10% — правило решения не поддерживает действия по ним.
- **Ноутбуки 01–03 описательные, а не конфирматорные.** Их цифры описывают наблюдаемое; ни одно утверждение о значимости на них не опирается.
- **A/B-предложение — это именно предложение.** Оно предопределено, рассчитано и выполнимо, но сам тест не проводился — наблюдаемые данные не использовались для «доказательства» эффекта.

## Рекомендации

В порядке приоритета, привязанные к числам выше:

1. **Провести предрегистрированный A/B-тест обнаружения премиума** (фильтры каталога / содержимое PDP), расчётный объём n = 26,608 на группу, ≈3 недели трафика премиума (p₀ = 5.82%, MDE = +10% относительного = 0.58 п.п., α = 0.05, мощность = 0.80). Это *единственная* рекомендация, которая влияет на доминирующую потерю на шаге просмотр→корзина в худшем пригодном для действий сегменте.
2. **Не действовать по семействам B и C.** Разрывы статистически реальны (4.87% / 7.32% относительного), но ниже предрегистрированного практического барьера 10%; изменение, достаточное для запуска, было бы обнаружимо, но наблюдаемый эффект — не оно.
3. **Пересматривать границу budget/mid только через новую предрегистрацию.** Поскольку budget–mid чувствителен к определению границы, любой будущий эксперимент на нижних сегментах должен явно переопределить свои диапазоны, а не молча переиспользовать эти.
4. Не сделано в этом проекте (вариант «месяц + время суток» в ноутбуке 06 — только разведка, вне конфирматорного списка): **месячный тренд** и **время суток**. Если у магазина выраженная сезонность или суточные паттерны — им нужен отдельный предрегистрированный разбор.
